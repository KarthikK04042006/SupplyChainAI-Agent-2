Data upload

CSV, with a header row. Column order does not matter, and re-uploading a file updates the rows it restates rather than duplicating them — so a corrected file can simply be sent again.

1 · Product catalogue

Creates or updates products. Only the columns present in the file are written, so a catalogue file will not zero the stock levels an inventory upload established.

Required: sku, name

Optional: category, lead_time_days, reorder_point, safety_stock, unit_cost, current_stock

2 · Inventory levels

Per-warehouse stock. Warehouses are created on first sight, and the product-level totals the risk scan reads are recomputed from these rows. A row whose SKU has no product yet is still stored, but stays off the inventory grid until the catalogue lands — so load the catalogue first.

Required: sku, warehouse, quantity_on_hand

Optional: on_order, warehouse_name, region

Drop a CSV here, or

3 · Demand history

What the forecasts are fitted on. A row whose SKU and date already exist updates that day's quantity. At least two days per SKU are needed before anything can be forecast.

Required: sku, date (yyyy-MM-dd), quantity

After uploading

Forecasts, alerts and the accuracy figure are produced by an inventory scan, not by the upload. Run one once the data is in.
